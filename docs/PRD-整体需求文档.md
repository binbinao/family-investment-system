# 齐家 · 家庭投资助手 — 产品需求文档

**版本**：v1.1  
**日期**：2026-03-23  
**状态**：MVP 定稿

---

## 1. 一句话定义

给三口之家用的投资记账本 + AI 分析助手。记清楚家里买了什么、赚了还是亏了、下一步怎么办。

---

## 2. 我们要解决什么问题

一个普通家庭管投资，实际痛点就三个：

1. **记不清**：持仓散落在多个 App 里，不知道家里一共投了多少、赚了多少
2. **看不懂**：想分析一只股票/基金，但不知道从哪里入手
3. **没人聊**：想跟家人讨论投资决策，但缺少一个共享的信息基础

我们不做交易系统，不做量化平台，不做社交产品。就做一个**记得住、看得懂、聊得了**的家庭投资工具。

---

## 3. 目标用户

一个三口之家（或类似规模的小家庭）：
- 1~2 人实际管钱，其他人偶尔看看
- 持仓 5~50 只标的（股票、基金、理财）
- 家庭投资资产几十万到几百万
- 不是专业交易员，但有一定投资经验

**用户规模**：单实例部署，服务 1 个家庭（自部署产品，不是 SaaS）。

---

## 4. 核心功能

### 4.1 家庭资产总览（首页）

打开就能看到家里的钱都在哪、赚了还是亏了。

| 功能 | 描述 |
|------|------|
| 总资产 | 家庭投资总市值、总成本、总盈亏、总收益率 |
| 日涨跌 | 今日盈亏金额和百分比 |
| 持仓列表 | 所有标的一览：名称、数量、市值、盈亏、占比 |
| 配置饼图 | 按资产类型（股票/基金/现金/其他）展示配置比例 |
| 今日晨报 | 最新一条 AI 晨报摘要 |

### 4.2 持仓与交易管理

| 功能 | 描述 |
|------|------|
| 添加持仓 | 输入代码、数量、成本价，手动添加一只持仓 |
| 记录交易 | 买入/卖出/现金分红/红利再投资，记一笔就更新持仓 |
| Excel 导入 | 提供 2 种模板（持仓导入 + 交易导入），批量录入历史数据 |
| 行情自动更新 | 持仓标的的最新价格自动获取，计算实时市值和盈亏 |
| 交易历史 | 按时间查看所有交易记录 |

**交易类型与处理规则**：

| 交易类型 | 对持仓的影响 |
|----------|-------------|
| 买入 | 增加数量，按移动加权平均更新成本价 |
| 卖出 | 减少数量，成本价不变，计算本次盈亏 |
| 现金分红 | 不影响持仓数量，记录现金流入 |
| 红利再投资 | 增加持仓数量（份额），成本价相应摊薄 |

**Excel 模板字段**：

持仓导入模板：

| 字段 | 必填 | 说明 |
|------|------|------|
| 标的代码 | ✅ | 如 600519、005827 |
| 标的名称 | ✅ | 如 贵州茅台、易方达蓝筹精选 |
| 资产类型 | ✅ | 股票 / 基金 / 债券 / 现金 / 其他 |
| 数量 | ✅ | 持有数量（股/份） |
| 成本价 | ✅ | 每股/每份成本 |
| 账户 | 可选 | 来源账户，如"张三-华泰"、"李四-天天基金"。方便对账 |

交易导入模板：

| 字段 | 必填 | 说明 |
|------|------|------|
| 标的代码 | ✅ | |
| 交易类型 | ✅ | 买入 / 卖出 / 现金分红 / 红利再投资 |
| 数量 | ✅ | |
| 价格 | ✅ | 成交价 |
| 日期 | ✅ | 交易日期 |
| 手续费 | 可选 | |
| 账户 | 可选 | 来源账户 |

**行情更新频率**（不同资产类型的更新节奏不同）：

| 资产类型 | 更新频率 | 说明 |
|----------|----------|------|
| 股票 | 交易时段每 5 分钟 | AKShare 实时行情接口（有被限流的可能） |
| 基金 | 每日 20:00 更新净值 | 基金净值通常 T+1 晚间公布，无法日内实时更新 |
| 债券/其他 | 每日更新 | 如获取失败则保留上次有效价格 |

**行情数据降级策略**：AKShare 为爬虫型开源库，存在被限流或接口变更的风险。当数据获取失败时：
- 展示最近一次有效价格，并标注"行情更新于 XX 时间"
- 连续 3 次失败后在首页显示黄色提示"行情更新中断，显示的是历史数据"
- 用户可以手动输入最新价格作为兜底

### 4.3 配置偏离提醒

不需要复杂的再平衡算法，就是一个**直觉性的提醒**。

| 功能 | 描述 |
|------|------|
| 设定目标 | 用户设定大类资产目标比例（如：股票 60% / 基金 30% / 现金 10%） |
| 偏离提示 | 当任一类别实际占比偏离目标超过 10%，首页显示黄色提醒 |
| 调仓建议 | 点击提醒后，显示"要回到目标比例，你需要买入/卖出 XX 约 XX 元" |

不自动执行任何操作，只是提醒和建议。

### 4.4 AI 对话（核心体验）

统一的 AI 分析入口，两种模式：

**快问模式**（默认）：
- 像聊天一样提问，DeepSeek 即时回复（秒级，通过 SSE 流式输出）
- 自动带入你的持仓上下文（"你当前持有 XX，成本 XX..."）
- 适合日常小问题："这只基金最近怎么样？"、"帮我看看这个 PE 是不是太高了"

**深聊模式**（手动切换）：
- 多角度分析，AI 分别从基本面、技术面、风险三个角度给出观点
- 耗时稍长（30s~2min），界面显示分析进度（"正在分析基本面..."→"正在分析技术面..."→"正在分析风险..."→"正在汇总结论..."）
- 适合重大决策："现在适不适合加仓新能源？"、"要不要止损这只股票？"
- 结论包含：总体建议、各角度观点、风险提示
- 如果某个角度的分析调用失败，跳过该角度并在结论中标注"技术面分析暂不可用"，不阻塞整体流程
- 用户可随时取消正在进行的深聊

两种模式共用同一个对话界面，深聊的结果也以对话形式展示。保留最近 30 天对话历史（30 天后自动清理，不归档）。

**限制**：
- 单日对话上限 100 次（快问 + 深聊合计）
- 深聊模式单次 Token 上限 30,000
- 所有回复附带"仅供参考，不构成投资建议"

> **注**：早期版本不做"置信度"展示——AI 自评的置信度往往不可靠，可能给用户造成虚假的确定感。如果未来需要，可以改为"本分析基于 X 条公开信息"的事实性表述。

### 4.5 每日 AI 晨报

每天早上自动生成一份与你持仓相关的市场摘要。

| 功能 | 描述 |
|------|------|
| 自动生成 | 每日 08:00 定时任务，AI 总结与持仓相关的市场新闻 |
| 内容 | 市场整体情绪（一句话）、持仓相关资讯（有就写，没有就说"今日无重要关联资讯"）、关注提示 |
| 推送 | 通过 Server酱/Bark 推送精简版到手机 + 邮件推送完整版 |
| 站内查看 | 首页展示最新一条，历史晨报可翻阅 |

**这不是一个独立的调研系统**，就是一个定时任务：拉取新闻 → 用 AI 结合持仓上下文总结 → 推送。没有多 Agent 协作，没有回溯机制，就是一次 AI 调用。

数据来源：AKShare（开源免费）新闻接口 + 东方财富资讯。

> **覆盖范围说明**：当前晨报主要覆盖 A 股和国内公募基金相关资讯。如果家庭持有 QDII 基金或港美股相关标的，相关海外资讯可能覆盖不到，后续可扩展数据源。

### 4.6 家庭共享

极简的多人共享，不搞权限体系。

| 功能 | 描述 |
|------|------|
| 家庭账户 | 一个家庭共享一套数据，所有人看到的数据一样 |
| 多用户登录 | 2~3 个账号，都能查看和编辑 |
| 操作记录 | 谁改了什么、什么时候改的，有个简单的操作日志 |
| 备忘录 | 共享的投资备忘录，支持关联标的代码（如输入 #600519 自动标记为"贵州茅台"相关），方便按标的过滤查看 |

不需要角色权限、不需要投票、不需要积分。三口之家吃饭时聊一句就是"决策会议"，备忘录记下来就行。

## 5. 不做什么（Out of Scope）

明确砍掉、不做的：

- ❌ 自动交易 / 与券商对接
- ❌ 多 Agent 调研系统（一个 AI 调用就够）
- ❌ 多专家圆桌讨论引擎（深聊模式的多角度分析足够）
- ❌ 决策投票 / 权重 / 贡献度追踪
- ❌ 复杂权限体系（管理员/成员/只读）
- ❌ 向量知识库 / 分层记忆系统
- ❌ WebSocket 实时推流（AI 流式输出通过 SSE 实现，不需要 WebSocket）
- ❌ 移动端 Native App
- ❌ 多家庭 SaaS
- ❌ 量化回测
- ❌ 多模型切换界面
- ❌ 月度准确率报告

## 6. 技术方案

### 6.1 架构决策：Next.js 前端 + FastAPI 后端

AKShare（行情/新闻数据源）和 DeepSeek SDK 都是 Python 生态，用 Python 做后端可以直接调用，不需要额外的胶水层。因此确定为**前后端分离**架构：

```
Next.js 前端 + FastAPI 后端
├─ 前端：Next.js 14+（React，8 个页面，SSR/CSR 混合）
├─ 后端：FastAPI（Python，API 服务 + 定时任务）
├─ 数据库：PostgreSQL（一个库，~12 张表）
├─ 缓存：Redis（行情缓存 + Session 存储）
├─ AI：DeepSeek API（一个模型，快问/深聊两种 prompt）
├─ 定时任务：APScheduler（内嵌在 FastAPI 进程中）
│   ├─ 每日晨报生成（08:00）
│   ├─ 股票行情更新（交易时段每 5 分钟）
│   ├─ 基金净值更新（每日 20:00）
│   └─ 持仓快照（每日收盘后）
└─ 部署：Docker Compose（一台服务器）
```

### 6.2 技术选型

| 层次 | 选型 | 理由 |
|------|------|------|
| 前端 | **Next.js 14+** | SSR 首屏快；React 生态成熟；响应式设计适配移动浏览器 |
| 后端 | **FastAPI** | Python 直接调用 AKShare / DeepSeek SDK；async 性能好；自动 API 文档 |
| 数据库 | **PostgreSQL** | 可靠、免费、功能够用 |
| 缓存 | **Redis** | 行情缓存（股票 TTL 5min、基金 TTL 24h）、Session 存储 |
| AI | **DeepSeek API** | 性价比最高、中文理解好、家庭场景足够 |
| 行情数据 | **AKShare**（开源） | 免费、覆盖 A 股/基金/债券。备选：Tushare（需注册 Token） |
| 消息推送 | **Server酱 + 邮件** | Server酱/Bark 个人免费可用，无需企业资质；邮件留档 |
| 认证 | **密码登录 + Session** | 密码 bcrypt 哈希存储；Session 存 Redis；公网部署强制 HTTPS |
| 部署 | **Docker Compose** | 一条命令启动全部服务（nginx + next + fastapi + pg + redis） |

> **为什么不用 Next.js 全栈？** AKShare 是纯 Python 库，无法在 Node.js 环境运行。如果用 Next.js API Routes 做后端，行情获取和 AI 调用都要通过子进程或独立微服务调用 Python，增加不必要的复杂度。直接用 FastAPI 做后端，Python 生态一步到位。

### 6.3 数据库表（约 12 张）

| 表名 | 用途 | 关键字段说明 |
|------|------|-------------|
| `users` | 用户账号（2~3 个） | id, username, password_hash, created_at |
| `holdings` | 持仓明细 | id, symbol, name, asset_type, quantity, cost_price, account(可选) |
| `transactions` | 交易记录 | id, symbol, type(买入/卖出/现金分红/红利再投资), quantity, price, fee, date, user_id |
| `price_cache` | 行情价格缓存（持久化） | symbol, latest_price, updated_at（Redis 缓存的持久化备份） |
| `snapshots` | 每日持仓快照 | id, date, total_market_value, total_cost, holdings_json（当日全部持仓快照） |
| `allocation_targets` | 目标资产配置 | id, asset_type, target_ratio |
| `ai_conversations` | AI 对话历史 | id, user_id, mode(快问/深聊), messages_json, created_at |
| `daily_reports` | 每日晨报存档 | id, date, content_markdown, summary, created_at |
| `memos` | 家庭投资备忘录 | id, content, related_symbols(关联标的), user_id, created_at |
| `operation_logs` | 操作日志 | id, user_id, action, detail, created_at |
| `settings` | 系统配置 | key, value（推送开关、晨报时间等） |
| `sessions` | 用户登录会话 | session_id, user_id, expires_at（也存 Redis，此表做持久化备份） |

### 6.4 AI 调用设计

不需要多 Agent 框架，所有 AI 功能都是**直接调用 DeepSeek API + 精心设计的 Prompt**。

| 场景 | 实现方式 |
|------|----------|
| 快问 | 单次 API 调用，system prompt 注入持仓上下文，通过 SSE（Server-Sent Events）流式输出到前端 |
| 深聊 | 3 次 API 调用（基本面/技术面/风险各一次）→ 1 次汇总调用，串行执行，每完成一步通过 SSE 推送进度 |
| 晨报 | 1 次 API 调用，prompt 包含持仓列表 + 当日新闻摘要（AKShare 获取） |

深聊不是多 Agent 系统，就是用**不同的 prompt 调同一个模型 3+1 次**，然后汇总。实现简单、效果足够。

**AI 不可用时的降级**：DeepSeek API 故障时，AI 对话和晨报功能暂停，但持仓管理、数据看板等核心功能不受影响。AI 页面显示"AI 服务暂时不可用，请稍后再试"。

### 6.5 安全要求

| 项目 | 要求 |
|------|------|
| 密码存储 | bcrypt 哈希，不存储明文 |
| Session | 存储在 Redis，设置过期时间（默认 7 天） |
| HTTPS | 公网部署必须启用（nginx 配置 Let's Encrypt 免费证书） |
| 数据备份 | PostgreSQL 每日自动 pg_dump，保留 30 天 |

### 6.6 成本预估

| 项目 | 月费用 |
|------|--------|
| DeepSeek API | ¥50~150（日常使用） |
| 云服务器（2C4G） | ¥50~100 |
| 域名 + HTTPS | ¥10/月 |
| **合计** | **¥110~260/月** |

一个家庭完全可以承受的成本。

## 8. 异常处理

| 场景 | 处理方式 |
|------|----------|
| AKShare 行情获取失败 | 展示上次有效价格 + 标注更新时间；连续 3 次失败显示黄色提示；用户可手动输入价格 |
| AKShare 新闻获取失败 | 晨报标注"今日资讯获取失败"，仍然推送（无资讯部分留空） |
| DeepSeek API 不可用 | AI 对话和晨报暂停；持仓管理/看板等核心功能不受影响；页面显示"AI 服务暂不可用" |
| Excel 导入数据有误 | 逐行校验，成功行正常导入，错误行高亮并显示原因（如"标的代码不存在"、"数量不能为负"），用户修正后可重新导入 |
| 标的代码输入错误 | 添加持仓时实时校验代码是否存在（通过 AKShare 查询），不存在则提示"未找到该标的" |
| 推送失败 | 记录日志，不阻塞主流程；用户可在站内查看晨报 |

## 9. MVP 开发计划

按优先级分 4 个阶段，总周期约 8~10 周：

### Phase 1（第 1~3 周）— 能用

- [ ] 项目骨架（Next.js + FastAPI + PostgreSQL + Redis + Docker Compose）
- [ ] 用户登录（密码 bcrypt + Session + Redis）
- [ ] 持仓 CRUD（添加/编辑/删除，手动输入最新价格）
- [ ] 交易记录（买入/卖出/现金分红/红利再投资，自动更新持仓）
- [ ] 首页总览（总资产、持仓列表、配置饼图）
- [ ] 基础测试 + Docker Compose 一键部署验证

**Phase 1 完成标准**：能把家里的持仓录进去，看到总资产和盈亏（行情暂时手动输入）。

### Phase 2（第 4~5 周）— 好用

- [ ] 行情自动更新（AKShare 股票/基金 + Redis 缓存 + 降级策略）
- [ ] Excel 导入（2 种模板，含校验和错误反馈）
- [ ] 每日持仓快照（净值曲线）
- [ ] 配置偏离提醒
- [ ] 测试 + 行情降级验证

**Phase 2 完成标准**：行情自动更新，能看到资产走势，能批量导入历史数据。

### Phase 3（第 6~8 周）— 聪明

- [ ] AI 快问（DeepSeek 集成、持仓上下文注入、SSE 流式输出）
- [ ] AI 深聊（多角度分析、进度反馈、结论汇总、可取消）
- [ ] 对话历史（30 天保留 + 自动清理）
- [ ] AI 降级策略验证

**Phase 3 完成标准**：能跟 AI 聊投资，快问秒回，深聊多角度分析。

### Phase 4（第 9~10 周）— 完整

- [ ] 每日 AI 晨报（定时生成 + 站内查看）
- [ ] Server酱/Bark 推送 + 邮件推送
- [ ] 家庭备忘录（含标的关联）
- [ ] 操作日志
- [ ] 移动端响应式适配
- [ ] HTTPS 配置 + 数据备份脚本
- [ ] 全流程测试

**Phase 4 完成标准**：每天手机收到晨报推送，产品可日常使用。

## 10. 未来可能做（但现在不做）

如果 MVP 用起来觉得确实需要，未来可以加：

- 多投资组合（按账户/策略分组）
- 负债管理
- 圆桌级深度讨论（真正的多 Agent）
- 微信服务号推送（需企业资质）
- 更多数据源（Tushare、新浪财经，覆盖港美股）
- 基金/股票筛选器
- 投资决策记录与回溯
- 多家庭支持

**原则**：先用起来，缺什么再加。不预设需求。

---

*这是一个给三口之家做的工具，不是给基金公司做的系统。简单、好用、能坚持用下去，比功能多更重要。*
